# Баланс · этапы 2–18

Автодеплой из GitHub на Linux-сервер: [настройка GitHub Actions и сервера](deploy/README.md).

Рабочая основа Telegram-бота на Python 3.12+, aiogram 3 и PostgreSQL 15+. Реализован личный учёт расходов с AI-категоризацией, личными правилами, распознаванием PDF/фотографий чеков и голосовым вводом. Основание: [ТЗ](docs/01-first-version.md) и [проект БД](docs/03-database-design.md). Код этапов 2–18 реализован; внешняя приёмка и параметры публичного запуска перечислены ниже.

## Что работает

- `/start` и `/help`: меню, повторная регистрация без дублей.
- `/add` или `/add 850,50`: сумма → описание → предложенная категория / ручной выбор → дата → карточка подтверждения. Можно начать с сообщения `850,50`.
- `/manual`: прежний ручной сценарий сумма → категория → описание → дата.
- `/ai`: информация о передаче описания в OpenAI и включение/выключение AI для пользователя.
- `/category`: изменение категории черновика; кнопка «Исправить категорию» после сохранения и кнопки «Категория №…» в истории.
- `/rules`: личные правила и отключение; `/rule кофе | Кафе и рестораны`: правило по целым словам.
- Начальные категории, свои категории, RUB/USD/EUR, личные и совместные бюджеты, несколько счетов.
- «Сохранить», «Изменить» (начать ввод заново), «Отмена» и `/cancel`. Старые кнопки изменённого черновика недействительны. После исправления категории можно нажать «Запомнить для меня».
- `/history [страница]`: по пять расходов с описаниями; `/report`: текущий месяц по категориям.
- `/accounts`: учётный остаток по проводкам. Начальный остаток нулевой, доходов пока нет, поэтому остаток отрицательный после расходов.
- `/settings` и `/settings Asia/Yekaterinburg`: просмотр настроек и смена часового пояса для новых черновиков.
- `/support`: контакт из `SUPPORT_CONTACT`.
- `/receipts`: обработка файлов без отдельного разрешения, автоматическое распознавание PDF/JPEG/PNG и страниц Telegram-альбома.
- Чек: продавец, дата, итог, валюта, позиции; исправления и подтверждение оплаты перед сохранением.
- «Чек» и «Позиции» после сохранения / в истории: оригинал и распознанный список товаров.
- `/voice`: русские голосовые сообщения до 3 минут и 15 МБ; расшифровка, редактирование полей и подтверждение перед сохранением.
- Работа только в личном чате.

## Запуск в текущем рабочем каталоге

Окружение `.venv`, локальный `.env` и отдельная БД уже подготовлены. `.env` содержит строки подключения и добавленный владельцем `BOT_TOKEN`. Бот зарегистрирован как @money_maxtyle_bot. Файл исключён из Git, права доступа — 600.

1. Создайте бота командой `/newbot` у [@BotFather](https://t.me/BotFather), если его ещё нет. [Инструкция Telegram](https://core.telegram.org/bots/tutorial#obtain-your-bot-token).
2. Откройте локальный `.env` в редакторе и заполните `BOT_TOKEN=...`. При желании укажите `SUPPORT_CONTACT=@ваш_username`.
3. Из корня проекта выполните:

```bash
.venv/bin/python -m balans
```

Откройте бота в Telegram и отправьте `/start`. При запуске приложение проверяет runtime-права БД, вызывает `getMe` и устанавливает список команд. Работает один polling-процесс; остановка — Ctrl+C. Если уже установлен webhook, приложение завершится с объяснением и не удалит его автоматически.

Подключение к Telegram и установка команд проверены; бот запущен локально. Токены в чат присылать не требуется. Подробности нового этапа: [AI-категоризация](docs/05-stage-3.md).

## Установка с нуля

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
```

Запустите локальный PostgreSQL. При доступе администратора БД:

```bash
.venv/bin/python scripts/dev_setup.py
```

По умолчанию используется `dbname=postgres host=localhost` под текущим системным пользователем. Для другого сервера задайте `POSTGRES_ADMIN_DSN` через окружение. Скрипт создаёт БД и две отдельные роли с уникальными именами и случайными паролями; существующий `.env` не перезаписывает. Он не устанавливает PostgreSQL и не меняет существующие БД. Административная учётная запись применяется только для provisioning; приложение получает ограниченную runtime-роль.

Для управляемой БД подготовьте отдельного владельца схемы и runtime-роль без `SUPERUSER`, `BYPASSRLS`, членства в роли владельца или права смены на неё. Владелец должен иметь право создавать схему и таблицу миграций в `public`. Заполните `.env` по `.env.example` и выполните:

```bash
.venv/bin/python -m balans.migrate
```

Runtime-роль по умолчанию берётся из `DATABASE_URL`; её можно явно задать через `--runtime-role`. Миграции выполняются отдельной строкой `MIGRATION_DATABASE_URL`. Бот её не использует. Применение атомарное, с блокировкой и контрольной суммой; повтор допустим, изменение уже применённого SQL отвергается. Новые изменения оформляйте следующей миграцией. Для резервирования данных используйте штатный `pg_dump` с подходящей резервной ролью; проверяйте восстановление до рабочего использования.

## Учёт и надёжность

`users → workspaces → memberships/accounts/categories → operation_drafts → operations/operation_revisions → journal_entries/postings`. Каждая финансовая сущность привязана к пространству, составные FK исключают ссылки на чужие категории и счета. Доступ к данным ограничен PostgreSQL RLS; runtime не имеет прав прямого изменения журнала. `save_expense()` создаёт операцию, версию, проводку и аудит в одной транзакции. Отложенный триггер проверяет соответствие суммы, счёта, даты и проводки.

Суммы — Python `Decimal` и PostgreSQL `numeric(20,6)`, ручной ввод RUB ограничен двумя знаками после запятой; неоднозначные/некорректные суммы не округляются молча. «Сегодня/вчера» относятся к дате начала ввода в сохранённом часовом поясе; бот показывает эту дату при запросе. Новая настройка зоны не меняет уже открытый черновик.

Черновики живут 24 часа, переживают перезапуск, истёкшие отменяются при следующем обращении пользователя. Сохранённые данные не отменяются командой `/cancel`.

На каждый Telegram update сохраняется ответ вместе с изменением состояния. Повтор использует тот же ответ; блокировка пользователя и уникальный источник операции защищают от конкурентного сохранения. Polling сдвигает offset только после обработки и ответа. Сбой после успешной доставки может дать повтор сообщения, но не второй расход. См. [правила getUpdates](https://core.telegram.org/bots/api#getupdates). Транзакции и соединения используют [контекстные менеджеры psycopg](https://www.psycopg.org/psycopg3/docs/basic/transactions.html).

## Проверка

```bash
.venv/bin/pytest -q
```

Тесты создают отдельную временную БД и две роли через `POSTGRES_ADMIN_DSN`, затем удаляют только их. Нужен работающий PostgreSQL и административные права для создания тестовой БД/ролей. SQLite или имитация БД не используются.

Проверено 124 тестов: суммы и даты, регистрация, ручной расход, история/отчёт/остаток, перезапуск, отмена/срок черновика, повтор update, параллельные подтверждения, RLS, подмена категории/кнопки, запрет прямого изменения проводок, старые кнопки после исправления, повтор миграций, приватность Telegram-чата и повтор после сбоя отправки. Для AI дополнительно проверены реальный SDK через тестовый HTTP-транспорт, ошибки/таймауты/отказы, некорректный JSON и чужие ID, отсутствие повторных API-вызовов, поздние результаты после отмены, исправления и приватность правил.

Google Sheets требует Google-ключа. Текущая версия работает локально; сервер, внешние резервные копии и платёжная приёмка ещё требуют настройки. См. [запуск и восстановление](docs/20-stage-18.md).

`/budget` — месячные лимиты; `/budgetday` — начало периода; `/notify` — настройки уведомлений (доставка выключена по умолчанию). Общие пространства: `/workspaces`, `/workspace`, `/members`; выдачи: `/funds`; документы и проверки: `/docs`, `/reviewqueue`. Описание каждого этапа находится в `docs/`.

## Настройка AI

В локальном `.env` предусмотрены:

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4.1-mini-2025-04-14
AI_TIMEOUT_SECONDS=10
AI_CONFIDENCE_THRESHOLD=0.75
```

`OPENAI_API_KEY` — отдельный ключ OpenAI API, не Telegram-токен. Ключ уже добавлен владельцем: реальный запрос категоризации и OCR на синтетических фото/PDF проверены. После добавления ключа перезапустите единственный процесс `.venv/bin/python -m balans`, в Telegram откройте `/ai` и включите AI. Правила и ручной выбор работают без ключа.

Проверка API без отправки пользовательских расходов:

```bash
.venv/bin/python scripts/check_ai.py
.venv/bin/python scripts/check_ai.py --eval
```

Первая команда отправляет один синтетический пример, вторая — десять. Это реальные API-запросы, отдельные от обычных тестов. При отсутствии ключа команды завершаются без вызовов API. Полный контракт, промпт, правила обучения и ограничения — в [описании этапа 3](docs/05-stage-3.md).


## Чеки: этап 4

1. Обработка чеков включена по умолчанию. `/receipts` показывает текущий набор и подсказку.
2. Отправьте фотографию или PDF/JPEG/PNG. Результат появится автоматически. Страницы многостраничного чека отправляйте одним Telegram-альбомом. Разные покупки отправляйте по отдельности.
3. Проверьте итог, дату, магазин и категорию. Подтвердите оплату, затем нажмите **«Сохранить расход»**.

Лимиты: 15 МБ на файл, 10 страниц и 30 МБ на набор, до 100 распознанных позиций. Поддерживается только RUB. PDF с паролем не обрабатывается. PDF-текст извлекается локально, все страницы рендерятся и вместе с текстом передаются модели; фото и сканы читаются через vision OCR. При неуверенном итоге/неизвестной дате бот просит ручное уточнение. Сумма внесённых денег и сдача не должны заменять итог; повторные расходы требуют отдельного подтверждения.

Оригиналы сохраняются в `.local/receipts` (каталог 700, файлы 600), исключены из Git. Можно изменить путь через `RECEIPT_STORAGE_DIR`. Срок хранения исходников — 30 дней; работающий бот очищает истёкшие файлы при запуске и затем раз в час. После истечения срока выдача оригинала блокируется, операция и распознанные позиции остаются. При выключенном боте физическая очистка произойдёт после следующего запуска. Для резервной копии нужны и БД, и каталог оригиналов.

Для обновления существующей установки: остановите polling-процесс, установите зависимости из `requirements.lock`, выполните `.venv/bin/python -m balans.migrate`, затем запустите `.venv/bin/python -m balans`. В текущей локальной установке миграция 003 применена и бот перезапущен.

Дополнительная реальная проверка OCR на трёх синтетических чеках:

```bash
.venv/bin/python scripts/check_receipt_ai.py
```

Команда делает три OpenAI API-запроса. Фото, текстовый PDF и PDF-скан проверены: итог 150 ₽, две позиции; внесённые 200 ₽ и сдача 50 ₽ не попали в сумму расхода. Это небольшая smoke-проверка, а не гарантия точности на всех чеках.

Подробности и границы: [этап 4](docs/06-stage-4.md).

## Голосовой ввод

Запишите и отправьте голосом один расход: «Вчера потратил 850 рублей на продукты». Проверьте карточку, при необходимости исправьте поля, затем нажмите «Сохранить». Используется существующий `OPENAI_API_KEY`; дополнительный ключ не нужен. Подробности и ограничения: [этап 5](docs/07-stage-5.md).

## Отчётность

- `/report` — текущий месяц; `/report сегодня`, `/report вчера`, `/report неделя`, `/report 2026-08` или `/report 01.09.2026 10.09.2026`.
- `/pdf [период]` — PDF с графиками категорий, динамикой и крупнейшими расходами.
- `/analyze [период]` — AI-анализ после подтверждения передачи сводных данных.
- `/csv [период]` — полный список выбранных операций, пригодный для импорта в Google Sheets.
- `/sheets` — подключение собственной Google-таблицы и прямой экспорт через кнопку в отчёте.

PDF, CSV и анализ используют один снимок данных. Подробности настройки Google и ограничений: [этап 6](docs/08-stage-6.md).

Голос, чеки и скриншоты доступны без отдельного разрешения на распознавание. `/voice off` и `/receipts off` отключают обработку, `/voice on` и `/receipts on` включают её обратно. Изображения распознаются автоматически, без сообщения о приёме и кнопок запуска; перед сохранением расхода остаётся проверка карточки. Миграция 019 включает обработку для существующих пользователей, которые ранее не давали отдельного согласия; ранее включённые и затем отключённые каналы остаются выключенными.

Карточки ввода показывают описание или позиции, сумму, категорию и дату, без бюджета, счёта, часового пояса, пояснения об источнике даты и статуса «Пока не сохранён». Голос выдаёт результат без промежуточного сообщения. Изображения распознаются автоматически; страницы Telegram-альбома собираются перед одним запросом. При нескольких позициях доступны «Разбить по категориям» и «Выбрать другую категорию». Разбиение предлагает категории товаров и показывает суммы по категориям; неполный перечень и расхождение с итогом блокируют разбиение. В отчёты входят только подтверждённые части, без общего расхода поверх них; исходные документы остаются прикреплёнными.
