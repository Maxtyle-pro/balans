# Техническое задание: Telegram-бот «Баланс» (Balan$)

Актуальная редакция для сдачи проекта · 15 сентября 2026 года.

Документ описывает итоговый объём реализованного проекта на основе `a50a529` с исправлениями UX от 14–15.09.2026 (миграции 034 и 035). Он заменяет первоначальный расширенный план. Основной пользовательский продукт — личный финансовый учёт с одним балансом. Сохранившиеся модули прошлых этапов и известные ограничения перечислены отдельно.

## 1. Назначение проекта

Разработать многопользовательского Telegram-бота на русском языке для учёта личных доходов и расходов. Пользователь отправляет текст, голосовое сообщение, фото чека, скриншот операции или PDF. Бот извлекает данные, сохраняет операции и показывает баланс и отчёты.

Бот ведёт учёт по внесённым данным. Он не подключается к банковским счетам, не выполняет переводы и не проверяет фактический остаток в банке.

Основной сценарий: «Кофе 250» → распознавание → сохранение расхода → компактная карточка с кнопкой «Изменить». Если пользователь выбрал режим подтверждения, перед сохранением показывается редактируемый черновик.

## 2. Пользователи и права

| Роль или состояние | Возможности |
|---|---|
| Новый пользователь | Выбор валюты, знакомство с ботом, принятие опубликованных условий и запуск пробного периода, если включена оплата |
| Пользователь с действующим доступом | Ввод и исправление операций, отчёты и распознавание в пределах квот |
| Пользователь с истёкшим доступом | История, экспорт, управление подпиской, поддержка и удаление данных; новые операции ограничены |
| Владелец сервиса | Административные функции и бесплатный доступ при соответствующей настройке |
| Администратор / поддержка | Действия в пределах назначенной роли |

Идентификатор пользователя — числовой Telegram ID. Повторный запуск бота не создаёт второй профиль. Финансовые данные изолированы между пользователями на уровне PostgreSQL RLS. Административная роль сама по себе не открывает чужие операции и оригиналы файлов.

## 3. Первый запуск и интерфейс

При первом запуске пользователь выбирает валюту: RUB, USD или EUR. Часовой пояс по умолчанию — Europe/Moscow. При включённой оплате бот предлагает отдельно начать пробный период, показывает условия и лимиты. Длительность пробного периода, цена и квоты задаются конфигурацией сервиса.

Основное меню:

| Кнопка | Действие |
|---|---|
| ➖ Расход | Подсказка свободного ввода и переход к ручному вводу |
| ➕ Доход | Ввод суммы дохода |
| 📋 История | Просмотр сохранённых операций |
| 📊 Отчёт | Сводка и выгрузка за выбранный период |
| 💰 Баланс | Учётный остаток |
| ⚙️ Настройки | Валюта, часовой пояс, начальный остаток, категории, режим сохранения, приватность, очистка истории |
| ⭐ Подписка | Доступ, срок, квоты и управление оплатой |
| ✉️ Написать разработчику | Текстовое обращение в поддержку |

Основное взаимодействие построено на кнопках. В списке команд Telegram для обычного пользователя опубликована только `/start`. Помощь доступна через `/help` и кнопку «Как пользоваться» при знакомстве с ботом. Часть старых команд сохранена для совместимости, но не является основным интерфейсом. Публичный обработчик Telegram блокирует старые команды создания/выбора счетов и общих бюджетов. Если раньше был выбран общий бюджет, показывается явная кнопка возврата в личный без удаления прежних данных.

Настройки позволяют выбирать автоматическое сохранение или сохранение после подтверждения. Автосохранение включено по умолчанию. Часовой пояс выбирается по городам; через совместимую команду можно задать другое поддерживаемое имя зоны.

Валюту можно изменить до появления сохранённых операций. При наличии истории смена блокируется: существующие суммы не переименовываются и не конвертируются автоматически.

## 4. Финансовые операции

Основные типы личного ввода:

- Расход — уменьшает баланс и учитывается в расходах периода.
- Доход — увеличивает баланс и учитывается в доходах периода.
- Начальный остаток — задаёт деньги, имевшиеся до начала учёта; влияет на баланс, но не считается доходом.

Начальный остаток может быть отрицательным. Повторный начальный остаток для того же счёта не допускается; одноимённая кнопка открывает существующую запись для исправления. Минус отрицательного остатка виден в карточке, истории и балансе.

В основе баланса лежат проводки. Для стандартного личного сценария: начальный остаток + доходы − расходы. Сохранённые возвраты, поддерживаемые финансовым модулем и обработкой изображений, увеличивают баланс и показываются в отчётах отдельно.

В интерфейсе используется один баланс, без выбора счетов при добавлении и исправлении. Суммы различных валют из старых данных не складываются в общий денежный итог.

Денежные значения обрабатываются через Python Decimal и точный десятичный тип PostgreSQL. Сохранение операции, её версии и проводки выполняется атомарно. Исправление создаёт новую версию и корректирующие записи журнала.

## 5. Ввод и распознавание

### 5.1. Текст

Свободное сообщение распознаётся без предварительной команды. Примеры: «Кофе 250», «Продукты 850 вчера», «Зарплата 50000».

Извлекаются тип, сумма, валюта, описание, дата и категория. Один текстовый запрос поддерживает до 8 операций и до 2000 символов. Несколько операций сохраняются отдельными записями и получают собственные карточки.

Если сумма не определена, бот запрашивает её. Неясное поступление требует выбора «Доход» или «Начальный остаток». Планы и сообщения без совершённой операции не должны превращаться в автоматическую запись. Внутренние переводы не входят в основной сценарий свободного ввода.

При отсутствии даты у текста или голоса используется дата исходного сообщения; текущий интерфейс отмечает такую дату предупреждением. При отсутствии описания используется «Без описания». Расход с неопределённой категорией получает «Без категории».

При недоступном распознавании предлагается ручной ввод. Ручной ввод расхода запрашивает сумму, категорию, описание и дату и завершается подтверждением.

### 5.2. Голос

Поддерживается одна операция в голосовом сообщении. Максимальная длительность — 180 секунд, размер — 15 МБ. Запись локально приводится к формату, пригодному для распознавания. Пустые, повреждённые и слишком длинные записи отклоняются.

Пользователь получает итоговую карточку или уточнение недостающих данных. Промежуточное сообщение о приёме и повтор полной расшифровки не являются частью обычного сценария. Исходный голосовой файл не сохраняется в постоянном файловом хранилище.

### 5.3. Фото, скриншоты и PDF

Принимаются фото Telegram, JPEG, PNG и безопасные PDF без пароля. Изображение можно отправить как фотографию или документ.

Технические пределы распознавания:

| Ограничение | Значение |
|---|---|
| Один файл | До 15 МБ |
| Набор файлов | До 30 МБ |
| Страницы PDF / изображений в обрабатываемом наборе | До 10 |
| Размер декодируемого изображения | До 24 млн пикселей |

Поддерживаются чеки, скриншоты банковских и торговых приложений, фото экрана кассы или терминала. PDF уже распознаётся, а не только хранится как вложение.

Бот извлекает читаемые суммы, валюту, дату, описание, продавца, статус оплаты, тип операции и позиции чека. Страницы Telegram-альбома собираются перед обработкой. Если найдены несколько операций, создаётся список отдельных записей.

Если дата не распознана, некорректна или находится в будущем, используется дата отправки исходного файла в зафиксированном часовом поясе пользователя. В карточке показывается обычный значок 📅 без предупреждения об отсутствующей дате. Дату можно исправить. Это согласованное правило для уже совершённых операций, а не поддержка будущих платежей; при ручном исправлении будущая дата отклоняется.

Если валюта не указана, применяется валюта учёта. Явно указанная другая валюта не пересчитывается автоматически; бот объясняет несовпадение. При отсутствии суммы требуется ручное уточнение.

Изображение без подтверждённого факта оплаты не сохраняется автоматически как оплаченная покупка. Пользователь подтверждает совершение операции или исключает запись.

В режиме подтверждения доступны изменение полей, исключение строк и разбиение полного чека на позиции с категориями. Сумма частей должна точно совпадать с итогом. Общий расход и его части одновременно не учитываются. В автоматическом режиме полный распознанный чек сначала сохраняется общей суммой; разбиение выполняется в сценарии подтверждения списка операций. После подтверждения общий расход атомарно отменяется, а части сохраняются. Ошибка оставляет исходную операцию; повторное подтверждение не создаёт дополнительные части. Оригинал сохраняет связи с частями.

### 5.4. Карточка результата

Карточка автоматически сохранённой записи содержит:

- Статус «Расход записан», «Доход записан» или «Начальный остаток записан».
- Описание и сумму с валютой.
- Категорию для расхода.
- Дату.
- Кнопку «✏️ Изменить».

После нажатия «Изменить» показываются только кнопки «Изменить сумму», «Изменить дату», «Изменить описание», «Изменить категорию» и «Отмена». «Сохранить изменения» появляется только после фактического изменения поля. В самой карточке результата остаётся только кнопка «Изменить». После сохранения временные сообщения редактора и прежняя карточка удаляются, затем отправляется одна обновлённая карточка с кнопкой «Изменить». В базе сохраняется новая ревизия той же операции, поэтому финансовая история и аудит не удаляются.

Повтор того же Telegram update не создаёт вторую операцию. Для повторной загрузки идентичного файла предусмотрено распознавание уже сохранённой записи. Перед автосохранением проверяются вероятные совпадения суммы, даты, валюты и доступных реквизитов между источниками. Пользователь выбирает отдельную операцию либо прикрепляет файл к имеющейся записи. Одинаковые текстовые записи не запрещены: это могут быть реальные повторные покупки. Проверка эвристическая, не гарантирует выявление всех дублей.

## 6. Категории

Категории принадлежат пользователю. В базовом наборе предусмотрены продукты, кафе и рестораны, транспорт, дом, здоровье, покупки, развлечения и другое; набор может настраиваться владельцем сервиса. Для нераспознанных расходов применяется отдельная категория «Без категории».

Пользователь может добавлять, переименовывать, скрывать и возвращать категории. Скрытая категория сохраняется в истории и не предлагается для новых записей.

Новую категорию можно создать со своим эмодзи или без него. Автоматический выбор эмодзи для произвольной пользовательской категории не выполняется. Для встроенных категорий используются заданные значки.

При распознавании учитываются личные правила и предложения ИИ. Исправления и правила одного пользователя не изменяют данные других пользователей. Идентификаторы категорий проверяются приложением.

## 7. История, баланс и отчёты

История выводится страницами по 5 записей, начиная с последних добавленных. В строке указан тип операции; действие называется «Изменить операцию». Кнопка «Найти» запускает поиск по описанию. Пользователь выбирает номер записи из показанного списка и переходит к её редактированию. Отменённые записи, если они есть, помечаются в истории.

Баланс рассчитывается по финансовому журналу и подписан как результат внесённых доходов, расходов и начального остатка.

Период отчёта выбирается кнопками: сегодня, текущая неделя, текущий месяц, прошлый месяц или собственные даты. Произвольный обычный период ограничен 366 днями и не включает будущее. Совместимая команда поддерживает отчёт за всю историю. В выбранном или сравниваемом периоде допускается до 5000 строк.

Краткий отчёт содержит доходы, расходы, возвраты при их наличии, разницу за период и основные категории. Разница за период не называется балансом. Сравнение с предыдущим периодом подписывается датами; процент не вычисляется при нулевой базе.

Доступные результаты:

| Формат | Назначение |
|---|---|
| Сообщение в Telegram | Быстрая сводка и кнопки следующих действий |
| PDF | Отчёт с таблицами и графиками |
| Детализированный PDF | Операции, доступные источники и приложения |
| CSV | Табличный экспорт кнопкой в отчёте; также поддерживается `/csv`, включая `/csv all` |
| ИИ-анализ | Пояснение агрегированных расходов после отдельного согласия |

Детализированный отчёт ограничивает суммарный объём исходных вложений 30 МБ и количество страниц PDF-приложений — 150. При превышении предлагается сократить период.

Обычные суммы и графики рассчитываются программой. Для ИИ-анализа передаются агрегированные данные; описания покупок и оригиналы не требуются. Сформированный отчёт является снимком: карточка показывает время формирования. Кнопка «Обновить» формирует свежий снимок; старые PDF/CSV остаются прежними.

CSV доступен в отчёте, поиск — в истории. Расширенные фильтры сохранены в совместимых командах. Google Sheets отключён. Поделиться готовым файлом можно обычной пересылкой в Telegram.

## 8. Подписка, квоты и уведомления

Реализованы базовая подписка Telegram Stars на 30 дней, автопродление, пробный период, управление продлением, обработка успешных платежей и возвратов. Цена, квоты, опубликованные условия и включение реальной оплаты задаются оператором сервиса.

Пробный период начинается отдельным действием пользователя. Его завершение не подключает оплату автоматически. После оплаты отмена автопродления сохраняет доступ до конца оплаченного периода.

Платёжные события проверяются по пользователю, сумме, валюте и назначению; повторное событие не начисляет доступ повторно. Платежи за бот хранятся отдельно от пользовательских финансовых операций.

Учёт квот: текстовый запрос, успешно обработанный файл изображения/PDF, секунды голоса и ИИ-анализ отчёта. Один многостраничный PDF считается одним файлом. Несколько операций в одном текстовом запросе не являются отдельными запросами квоты. Резервирование и освобождение квот выполняются на уровне БД.

В приложении предусмотрены ежемесячные сводки, уведомления о квотах, сроках доступа и хранения файлов. Ежемесячная сводка включается при старте пробного периода. Управление доступно через «Настройки» → «Данные и приватность» → «Уведомления». Явное отключение уведомлений исполняется; служебные сообщения о квотах и хранении не смешиваются с ежемесячной сводкой.

Дополнительные пакеты ИИ, расширенный тариф и платное продление хранения реализованы только в демонстрационном режиме для разрешённых аккаунтов. Они не являются готовыми к продаже дополнениями. Демонстрационные экраны явно сообщают, что Stars не списываются. Обычному пользователю не предлагаются кнопки покупки этих дополнений: доступны подписка, ручной ввод, срок квоты и скачивание файлов.

## 9. Файлы, приватность и удаление

Оригиналы изображений и документов хранятся в приватных каталогах сервиса. В БД находятся метаданные, контрольные суммы и связи с операциями. Финансовые операции остаются в истории независимо от срока хранения оригинала.

Базовый срок хранения изображений и документов — 90 дней. Перед плановым удалением система формирует уведомление и предлагает скачать архив. Плановая очистка учитывает подтверждённую доставку предупреждения и минимум 7 дней после него, поэтому фактическое хранение может превышать 90 дней.

Совместимая команда `/retention off` отключает хранение личных оригиналов; это отдельный сценарий очистки. Возможность реального платного продления ограничена статусом реализации из раздела 8.

В настройках доступна «Очистить историю». После отдельного подтверждения удаляются личные финансовые записи и связанные данные, баланс обнуляется, файлы ставятся в очередь удаления. Подписка, настройки и использованный лимит ИИ сохраняются. Сообщения Telegram остаются.

Удаление профиля доступно из настроек приватности и через `/delete`: подтверждение, немедленное закрытие доступа, последующее удаление личных данных и файлов. В интерфейсе заявлен срок до 7 дней для активных данных и до 30 дней для резервных копий; соблюдение срока копий зависит от настроенного хранения резервов. Восстановление применяет реестр удалений.

«Настройки» → «Данные и приватность» открывает политику, файлы, удаление профиля, уведомления и распознавание. Переключатели текста, голоса и изображений показывают фактическое состояние и действительно включают/отключают обработку.

## 10. Поддержка и управление сервисом

«Написать разработчику» принимает текст до 3000 символов. Обращение сохраняется и доставляется разработчику вместе с Telegram ID отправителя. Финансовые записи и вложения автоматически к обращению не добавляются.

Административная веб-панель предусматривает пользователей, роли, тариф, платежи, квоты, ИИ-задачи, очередь, обращения, настройки и аудит. Вход использует одноразовый код и TOTP. Действия ограничены ролью.

У владельца предусмотрена отдельная статистика активности пользователей. Диагностический просмотр финансовых данных требует отдельного разрешённого снимка; обычная панель не открывает чужую историю.

## 11. Архитектура и технологии

| Компонент | Реализация |
|---|---|
| Язык | Python 3.12+ |
| Telegram | aiogram; polling либо защищённый webhook |
| База данных | PostgreSQL, psycopg, миграции, RLS |
| Состояние диалога | Черновики и ожидаемые действия в БД |
| Фоновые задачи | Устойчивая входящая очередь и фоновые обработчики |
| ИИ | Адаптеры OpenAI и проверка структурированных ответов |
| Медиа | Ограниченная обработка изображений, PDF и аудио |
| Отчёты | ReportLab, PDF и CSV |
| Администрирование | Веб-панель aiohttp |
| Развёртывание | Docker Compose, GitHub Actions, SSH |
| Эксплуатация | Healthcheck, скрипты резервного копирования и восстановления |

Приём update, финансовое состояние и сохранённый ответ защищены от повторной обработки. Бот фиксирует исходную дату и часовой пояс, чтобы задержка ИИ не меняла дату операции.

Один процесс бота защищён блокировкой от одновременного запуска второго экземпляра с той же БД. Внутри процесса настраиваются 1–16 обработчиков входящей очереди. Горизонтальное масштабирование нескольких одинаковых экземпляров не заявляется как готовая возможность.

Файлы расположены в приватном файловом хранилище на сервере; внешнее объектное хранилище не является обязательной частью текущей реализации. Секреты задаются окружением вне исходного кода.

## 12. Проверка и критерии приёмки

14.09.2026 в локальной редакции с UX-исправлениями регрессионный набор завершился результатом **349 passed**, с двумя предупреждениями библиотеки pypdf. После расширения проверок поиска и очистки после разбиения отдельно повторно пройдены все 18 UX-тестов. Проверено также применение миграции 034 на базе с существующими операциями, сохранение проводок и ограничений доступа. Тесты используют отдельную временную PostgreSQL и синтетические данные. Проверки ИИ преимущественно используют подменные ответы и HTTP-моки.

| Проверяемый сценарий | Результат |
|---|---|
| Повторный старт | Один пользовательский профиль |
| Свободный текст с несколькими операциями | Отдельные карточки и записи |
| Неопределённая сумма | Уточнение без сохранения выдуманной суммы |
| Неясное поступление | Выбор дохода или начального остатка |
| Файл без распознанной даты | Дата отправки и обычный значок 📅 |
| Неподтверждённая оплата | Уточнение перед записью |
| Режим подтверждения | Запись после подтверждения |
| Разбиение чека до и после автоматического сохранения | Сумма частей равна итогу, двойного общего расхода нет |
| Повтор update / нажатия сохранения | Одна операция |
| Исправление записи и смена типа | Новая версия, история типов и корректный баланс |
| Удаление одной записи | Подтверждение, пересчёт баланса, повтор безопасен |
| Прикрепление чека | Одна операция, оригинал доступен для скачивания |
| Сбой посередине разбиения | Исходный расход сохранён, частичных записей нет |
| Повтор файла после разбиения | Общий расход повторно не создаётся |
| Настройки обработки и уведомлений | Фактическое включение и отключение |
| Поиск, CSV и обновление отчёта | Доступны из кнопок истории и отчёта |
| Начальный остаток 1000, доход 500, расход 339 → 300 | Итоговый баланс 1200 |
| Чужая операция или подменённая ссылка | Доступ не предоставляется |
| Ошибка ИИ | Обработка ошибки и ручной ввод |
| Повтор события оплаты | Нет повторного начисления доступа |
| Очистка истории | Баланс обнулён; настройки и подписка сохранены |

Проект развёрнут через CI/CD; последняя подтверждённая в рамках работы доставка версии `a50a529` — [GitHub Actions, 14.09.2026](https://github.com/Maxtyle-pro/balans/actions/runs/34841859137).

Количество тестов не является оценкой точности распознавания реальных чеков. Точность 98%, качество категорий 90%, круглосуточная доступность и полные задержки обработки не заявляются как измеренные результаты. Платёжная приёмка с реальными списаниями, внешние резервные копии и эксплуатационные показатели проверяются отдельно.

## 13. Границы версии и дальнейшие улучшения

В репозитории сохранены расширенные модули прошлых этапов: несколько счетов, переводы, совместные бюджеты, выдачи и сверка, проверка документов, закрытые периоды, бюджетные лимиты и передаваемые отчёты. Они не входят в обычную навигацию итогового личного бота. Старые документы этапов описывают историю разработки, а не обязательный объём интерфейса для сдачи.

Оставшиеся границы: эвристическая проверка дублей, отсутствие автоматической конвертации валют и реальной продажи дополнений, ограничения объёма распознавания и отчётов. Смена типа связанных возвратов и переводов не предоставляется; общий учёт не входит в публичный личный интерфейс.

Исходные находки и статусы исправлений приведены в [аудите проекта](27-project-ux-audit.md). Для установки обновления на сервер потребуются миграции 034 и 035; развёртывание выполняется штатным CI/CD из `main`. Развитие должно сохранить простой ввод, один баланс и возможность исправления результата пользователем.
