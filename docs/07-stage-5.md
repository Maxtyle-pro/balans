# Этап 5 — голосовой ввод

Реализован приём Telegram Voice в личном чате: распознавание русской речи → структурированный разбор одного расхода → редактируемая карточка → явное сохранение. Существующие расходы, чеки, категории и личные правила продолжают работать.

## Использование

1. Отдельное разрешение не требуется: голосовой ввод включён по умолчанию. После ручного отключения включите его командой `/voice on`.
2. Записать, например: «Вчера потратил восемьсот пятьдесят рублей на продукты».
3. Сверить сумму, дату, описание и категорию. Бот сразу показывает карточку результата без предварительного сообщения о распознавании. Кнопки «Сумма», «Дата», «Описание», «Категория» позволяют исправить поля без повторной записи и AI-вызова.
4. Нажать «Сохранить». До этого журнал и отчёты не меняются. `/cancel` отменяет черновик или незавершённую обработку. `/voice off` отключает новые запросы и отменяет активный голосовой черновик.

Один совершённый расход в RUB, личный бюджет и счёт «Основной». Несколько независимых расходов, переводы, доходы, возвраты, планы и другие валюты не записываются. Бот предлагает уточнить ввод. Нераспознанная сумма/дата/категория требует ручного заполнения; кнопка сохранения появляется только после заполнения обязательных полей. Личные включённые правила категории применяются поверх AI; исправления категории можно запомнить прежним механизмом.

«Сегодня» и «вчера» считаются от времени исходного голосового сообщения в зафиксированном часовом поясе пользователя. Если дата не произнесена, AI предлагает дату сообщения с пояснением. При исправлении дата помечается как введённая вручную. Совпадение даты и суммы с существующим расходом любого источника требует подтверждения «Это другая покупка».

## Обработка и хранение

Лимиты: 3 минуты, 15 МБ. Telegram-метаданные проверяются до скачивания; фактический объём ограничивается при скачивании, длительность — по декодированным семплам. PyAV/FFmpeg из Python-wheel локально преобразует OGG/Opus (а также другие поддержанные Telegram Voice контейнеры) в mono WAV 16 kHz. Отдельная установка ffmpeg не нужна. Декодирование выполняется в отдельном процессе с лимитом CPU 20 секунд и времени 25 секунд, на Linux — также памяти. Пустая/повреждённая запись и цифровая тишина отклоняются до API. Шум не гарантирует успешного распознавания; любая карточка требует проверки человеком.

Оригинал и WAV находятся только в памяти и не сохраняются в файловое хранилище бота. Расшифровка, результат и состояние задания сохраняются в PostgreSQL под RLS владельца. Длинные цифровые реквизиты маскируются до хранения и разбора. Расшифровка ограничена 6000 символами и используется для разбора; в карточке показывается описание операции без повторения расшифровки. Это не удаляет исходное голосовое сообщение из Telegram. Обработка OpenAI регулируется настройками и правилами провайдера; `store=False` применяется к Responses API, не является обещанием нулевого хранения провайдером.

`voice_jobs` фиксирует задание до платного запроса, а `telegram_updates` связывает его с уникальным обновлением. Внешние запросы идут вне транзакций БД. Ответы кешируются; повтор обновления не вызывает AI повторно. При таймауте/аварии нет автоматического повторного платного запроса: пользователь отправляет запись заново или вводит расход вручную. Прерванное задание освобождается по трёхминутной аренде, `/cancel` освобождает сразу. После отмены или отключения обработки поздний AI-ответ не создаёт черновик.

Финансовая запись создаётся атомарно существующей функцией `save_expense`, с источником `voice`, после проверки версии карточки. Исправление категории сохранённой записи сохраняет источник и не создаёт повторных проводок. Runtime-роль не получает прямую запись в журнал.

## Настройка и проверка

Тот же `OPENAI_API_KEY`, что для этапов 3–4. Необязательный `OPENAI_TRANSCRIBE_MODEL=gpt-4o-mini-transcribe`; разбор использует `OPENAI_MODEL`. Распознавание имеет таймаут 60 секунд, разбор 30 секунд; SDK retries=0. Промпт: `balans/prompts/voice_v1.txt`. Миграция `004_voice.sql` добавляет настройку обработки, задания и происхождение расхода.

```sh
.venv/bin/pip install -r requirements.lock
.venv/bin/python -m balans.migrate
.venv/bin/python -m pytest -q
.venv/bin/python -m balans
```

Для реального API smoke-теста на macOS можно создать синтетическое аудио, не затрагивая финансовую БД:

```sh
mkdir -p .local/voice-smoke
say -v Milena -o .local/voice-smoke/expense.aiff 'Вчера потратила восемьсот пятьдесят рублей на продукты.'
.venv/bin/python -m scripts.check_voice_ai .local/voice-smoke/expense.aiff
```

Проверены также синтетический OGG/Opus, фактические ограничения аудио, API-ошибки без повторов, приватность, Telegram-транспорт, повторная доставка, отмена в ходе обработки, ручные исправления, подтверждение и дубли. Это функциональная проверка, не оценка точности на пользовательском датасете из ТЗ. Сервер пока использует последовательный polling: длительное распознавание задерживает следующие сообщения; масштабируемая очередь и SLA из полного ТЗ остаются последующими задачами.

API интегрирован по [официальной документации OpenAI Speech to text](https://developers.openai.com/api/docs/guides/speech-to-text) и [описанию модели](https://developers.openai.com/api/docs/models/gpt-4o-mini-transcribe).
