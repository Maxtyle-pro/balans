# Этап 15 — подписка Stars и квоты

`/subscription` показывает состояние, цену, период, квоты и опубликованные условия. Счёт создаётся после подтверждения условий. `/renewal` управляет автопродлением, `/terms` и `/paysupport` открывают условия и контакт поддержки.

Тариф — рекуррентная подписка 30 дней, XTR, без обещанного рублёвого эквивалента. Проверены актуальные [правила цифровых платежей](https://core.telegram.org/bots/payments-stars) и [Bot API](https://core.telegram.org/bots/api#createinvoicelink): период 2592000 секунд, сумма до 10000 Stars. Код использует createInvoiceLink, answerPreCheckoutQuery, successful_payment, refunded_payment, editUserStarSubscription и refundStarPayment.

Оплата по умолчанию выключена. Для настройки нужны OWNER_TELEGRAM_ID, SUBSCRIPTION_STARS, квоты TEXT_MONTHLY_QUOTA / VOICE_MONTHLY_SECONDS / IMAGE_MONTHLY_QUOTA, опубликованные TERMS_URL и SUPPORT_CONTACT. TRIAL_DAYS по ТЗ — 7. После утверждения параметров оператор запускает `python -m scripts.configure_billing`. Это изменяет тариф с отдельной версией условий; оплаченные квоты сохраняются в снимке счёта. В `.env.example` нет выдуманной цены.

Доступ: пробный, оплаченный, истёкший, бесплатный владелец, приостановленный. Общий бюджет использует подписку руководителя. Истечение блокирует создание финансовых операций на уровне БД, оставляет историю и экспорт. Отмена продления сохраняет оплаченный период. Возврат прекращает доступ только по возвращённому платежу; настройка автопродления изменяется отдельно.

Проверяются пользователь, payload, XTR, сумма; pre-checkout ещё не предоставляет доступ. Уникальный charge_id, журнал событий и абсолютный срок из Telegram защищают от повторов и событий не по порядку. Возврат, пришедший раньше успешного платежа, не позволяет позднему событию заново открыть доступ.

AI-квоты резервируются транзакционно по владельцу бюджета и календарному месяцу UTC. Для текста — запросы, голоса — секунды декодированного WAV, изображений — файлы пакета. Неудачные/отменённые задания освобождают резерв, успешные потребляют; повтор той же успешной задачи не списывает квоту снова. Бесплатному владельцу коммерческие квоты не применяются, технические ограничения сохраняются.

Входящие Telegram updates фиксируются в БД до продвижения offset. Тяжёлая обработка вынесена в отдельную входящую очередь; pre-checkout обрабатывается polling-потоком без ожидания AI. После завершения исходный JSON входящего события очищается. Неудачные задания ограничены десятью попытками, затем доступны для операторской проверки.

`python -m scripts.reconcile_stars` сверяет историю Telegram. Подтверждённые возвраты учитываются; неизвестный входящий платёж заносится в аудит для проверки точного срока (Stars history его не содержит). Автоматически придумывать срок продления нельзя. Возврат оператором использует предварительно сохранённый запрос с причиной; неоднозначный ответ Telegram не повторяется автоматически.

Напоминание об окончании доступа использует настройки доставки и тихие часы. Недостаток Stars определяется истечением оплаченного срока при отсутствии подтверждённого продления; отдельное неподтверждённое событие «банк отказал» не выдумывается.

Внешняя приёмка остаётся: утвердить цену/квоты/условия и владельца, проверить оплату и продление в выделенной Telegram test environment. В рабочем боте платежи выключены, реальные Stars не списывались. Административный интерфейс возвратов — этап 16.

Проверка: 197 тестов полного набора, включая повтор/порядок платежей, возврат, истечение, права, общие квоты с конкурентными запросами, восстановление входящей очереди и запрет повторного возврата.
